Q3 · Productivity — decided: chat-native doc/URL review shape settled

Your call: no separate feature or tab — "just call it chat, and it should render if the user adds something like a URL; default is text." So the Chat input stays exactly what it is today, and gains one behavior: when a message contains a URL, the server fetches and extracts the page, renders it as a document card in the conversation, and answers the question with retrieval over both the document and the transcript corpus. A plain-text message behaves exactly as it does now.

How it renders — a document card in the thread, no new tab

  • The card — the extracted document appears above the answer as a collapsible, sectioned card. Feedback points anchor to sections; clicking an anchor expands and highlights the section it critiques. Corpus citations keep their existing watch-at links.
  • The conversation keeps the doc in scope — follow-up questions in the same entry re-use the fetched document (pinned by id), so "now check the experience section" just works without re-fetching.
  • Render extracted text, not the live page — iframes break on X-Frame-Options/CSP for most real sites and screenshots need a headless browser; readability-extracted text works everywhere and is what retrieval uses anyway. A screenshot thumbnail can come later if visual critique becomes a real use case.
  • Pasted documents — a long paste (a resume, an invite) can be offered the same treatment with a "treat as document?" affordance, but the decided trigger is a URL; plain text stays the default path.
Two guardrails, both now v1-required since URL fetch is the trigger: the fetcher ships with SSRF guards from day one (http/https only, private-range IPs blocked, short timeout, size cap) · fetched document text lives in a gitignored store referenced by id from the history entry — never inlined into dashboard/chat_history.json, which is committed to git.

Still on the shelf, unblocked by this: the Trends dashboard (dated Neo4j claims → entity timelines — the graph's unique payoff) and prompt templates (< 1 session, ships alongside anything).

Q5 · "Evals — can I do better than LLM-as-judge?"

First, credit where due — you are not only using LLM-as-judge today:

RAGAS judgefaithfulness · relevancy · precision, with sample spread
Deterministic IRrecall@k · MRR · nDCG vs 14 labeled questions
Reference-basedanswer correctness / similarity vs golden answers
Win-ratessame-judge contests only
CI gateeval-regression check on every PR
Cell cacheconfig-fingerprinted, cheap re-runs
The one real hole: the judge is grading its own homework. Answers come from deepseek-v4-flash and are judged by deepseek-v4-flash. Self-preference bias is well-documented, and it's the first question anyone rigorous will ask about your scoreboard. The fix is already built: YT_AGENT_JUDGE_MODEL exists in config and is simply unset. Point it at a different provider and re-run the matrix (cache scopes judging config, so only judged cells re-pay).
UpgradeWhat it buysEffort
1Independent judge modelKills the self-grading critique. Config-only + one matrix re-run.Tiny
2Position-swapped pairwise judgingWin-rates from real A/B comparisons (judged both orders to cancel position bias) instead of ranking absolute composites — much more reliable for "which setup is better".Small–medium
3Human calibration passHand-label ~30 (question, answer) pairs yourself; report judge–human agreement (Cohen's κ) in the provenance bar. Turns "LLM-as-judge" into "calibrated LLM-as-judge".Small (mostly your time)
4Negative controlsAdd unanswerable / out-of-corpus questions to the golden set and score abstention. Catches the failure mode judges are blindest to: confident answers from nothing.Small
5Bootstrap CIs on the scoreboardError bars on composites — at n=5 the rows already carry a "thin" badge; CIs make the uncertainty honest at any n.Small
6NLI groundedness cross-checkA small local entailment model verifying answer sentences against contexts — a cheap, deterministic second opinion on faithfulness (RAGAS judging is slow on long answers today).Medium
Your call: deferred for now. None of these are green-lit yet — the table stays as the backlog. When you do pick this up, start with #1: it's one env var (YT_AGENT_JUDGE_MODEL) plus a cached matrix re-run, and it's the finding a reviewer will hit first.
