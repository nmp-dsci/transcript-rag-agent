2Deploy + harden — a 20-seat, budget-metered demo impact: very high 3–5 days risk: medium

A URL on the resume answers "is this real." The senior-level move is what you don't build: a ≤20-account allowlist with per-user LLM budgets, not a signup funnel — no Cognito, no user DB beyond the ledger, no billing. Cost is bounded by construction rather than by hoping, and the metering itself is a demonstrable engineering artifact: "here is how I stopped a public LLM app from being a blank cheque" is a better interview story than the deploy. The app is single-tenant by construction (chat_history.json is a shared, git-tracked file; the document store and matrix runner are global singletons) — deploy demo mode around that and document the multi-tenant gap in the case study rather than spending three weeks closing it.

Cost is bounded three ways, deliberately layered. A ≤20-account allowlist caps who can spend at all (structural, no logic to fail); a tracked per-user daily budget caps how much each one can; a global daily ceiling caps the total even if every user maxes out. Worst case is arithmetic you can state in advance — 20 × per-user cap — rather than a number you discover on a bill. All three fail closed: on any doubt the request is refused, never allowed through unmetered.

Risks: a metering bug that under-counts is the failure mode that matters — meter before the call, not after the response, so a timeout or crash still consumes budget · public SSRF surface — already guarded in src/documents/fetch.py, worth a line in the write-up · shared demo state if demo mode is skipped.

4Eval credibility pack impact: medium 1–2 days risk: low

Independent judge (one env var + rerun), bootstrap CIs on the scoreboard, golden set 20 → 40. Real, but it polishes an existing strength rather than closing a gap — so it is folded into #1 (the judge rerun) and the rest is a background task, not a standalone project.

5Deep research mode impact: medium-low ~1 week risk: medium

On-trend but rapidly becoming commodity — every framework ships a tutorial, and this repo already has the agentic ReAct loop and recursive multi-hop paths a research mode would extend. The only differentiating version is evaluating long-form research (citation precision, rubric scoring of reports), which is real work for a modest resume delta. Backlog unless a target role explicitly emphasizes agentic research.

What NOT to build, explicitly: user accounts, multi-tenancy, per-user billing, Cognito, a serverless rewrite. Weeks of undifferentiated product plumbing that signals nothing about AI engineering. The case study gets a short "what production multi-tenancy would require" section instead — the analysis is the signal, not the implementation.
