4.4 — Golden set extension, eval-matrix, and the Scoreboard/Experiments pivot

Today Scoreboard and Experiments look like two views of the same thing, but they read from two different, disconnected data sources — that's the actual source of confusion. This plan proposes pointing both at the same controlled eval set (the golden-set matrix), and reframing the live Chat tab as exactly that: a separate, live sandbox, not a scoring input.

4 · Coverage gap: more than half the corpus has zero golden questions

⚠ 13 of 23 corpus videos — the entire job-search / résumé / LinkedIn content category — have no golden-set coverage at all

DOMAINS in src/evals/golden.py only allows ("property", "ai-coding", "corpus") — there isn't even a domain value to classify these videos under. They span 10 different channels: Ashish Pratap Singh, Farah Sharghi, Greg Langstaff, Headless Headhunter, HubSpot Marketing, Jash Radia, Kevin Stratvert, Sarah Li, Stefan Masnikovic, Zen van Riel. These are exactly the 13 videos backfilled with GraphRAG extraction earlier today — graph_rag currently has no golden question that even exercises them.

Separately, the golden set's corpus metadata block still says 10 videos, 281 chunks, verified 2026-07-21 — stale now that the corpus is 23 videos, 488 chunks.

5 · Implementation plan

P1

Repoint Scoreboard to read from the eval set backend

  • src/api/scoreboard.py stops reading dashboard/chat_history.json and instead loads a committed matrix-*.json run (shape already close: per-setup summary.averages, per-entry scores).
  • resolved Scoreboard gets a run picker — a dropdown of every committed matrix run (newest first, same list Experiments already sorts), not just the latest. See the mockup below.
  • Reuse the existing leaderboard / win-rate UI in ScoreboardView.tsx — this is a data-source swap plus one new control, not a redesign.
  • Chat's live ask-and-judge flow is untouched — it just stops being an input to Scoreboard.
P2

Extend the golden set content

  • resolved Add career to DOMAINS in src/evals/golden.py for the job-search/résumé/LinkedIn videos.
  • resolved ~5-6 new questions covering the 13 previously-uncovered videos as a category (not one per channel) — a mix of local + one global, matching the density ai-coding gets today.
  • Refresh the stale corpus metadata block to 23 videos / 488 chunks, re-verify existing expected_chunk_ids are still valid (chunking config hasn't changed, so they should be).
P3

Run the judged comparison matrix eval

  • eval-matrix across all 4 setups (rag_llm, rag_llm_recursive, rag_agent, graph_rag) over the extended golden set, judged.
  • Cheap: the existing per-cell cache (matrix_cache.py) means only the new questions cost LLM calls — the original 14 × 4 cells are cache hits.
  • Commit the new matrix-*.json to evals/runs/.
P4

Verify + document gate

  • Confirm Scoreboard and Experiments both reflect the new run, all 4 setups visible without any manual live-asking.
  • Update evals/runs/README.md — it documents ablation-*.json and eval-*.json today but never mentions matrix-*.json at all.
  • Tests + lint + mypy gate as usual.
P5

In-app "run eval matrix" trigger in scope

  • resolved Bundled into 4.4, not deferred.
  • A button in Experiments kicks off a matrix run as a background job with live progress — same pattern as the ingestion queue: an IngestionQueue-style job runner + SSE broadcast, not a blocking request.
  • On completion the new matrix-*.json is committed and both Scoreboard (once the run is selected in its picker) and Experiments refresh automatically.
