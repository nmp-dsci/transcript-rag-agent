# Frontend acceptance scripts

One script per vertical slice. Each drives a real browser through the click path
a reviewer would take at http://127.0.0.1:8021 and asserts on what the page then
shows — not on what the API returns.

```bash
uv run python -m src.cli serve --port 8021          # in one terminal
PYTHONPATH=. uv run --group demo python -m demo.validate.v0_judge   # in another
```

Each run writes `artifacts/<slice>/verdict.json` — the checks, their pass/fail,
and the screenshot each was taken against. Verdicts are committed, because "the
slice passed" is a claim that should survive in the repo with its evidence;
screenshots are regenerable and `artifacts/.gitignore` drops them. It drops
`*.jpg` as well as the `*.png` that `harness.py` writes, because an evaluation
that ran without Playwright saved the other extension and the driver that
happened to work is not a reason to keep one slice's captures and discard
another's. Put the finding in the check's `detail`, not in the frame.
`STATUS.md` reconciles every verdict against the plan and is generated by
`status.py`; never hand-edit it.

## The rule these scripts exist to enforce

A slice whose hypothesis cannot be seen in the frontend fails review even if
every automated gate passed. So the script asserts the *visible* claim: the
metric table lists eight rows, the capped cell carries its reason, the theme
opens to chunks from two different videos.

## Who writes them

Not the agent that built the slice. Generation and evaluation run as separate
agents with separate contexts: the builder writes the feature and its unit
tests, an independent evaluator writes the script here and decides pass/fail.
An implementer validating their own work tests what they remember building.

Everything under `demo/validate/` is evaluator-owned, so amending a script you
inherited is legitimate and has been done. Amending it *downwards* is the one
move this directory cannot police on its own — see "If you loosen a check".

A past evaluator's verdict is a record, not a draft. Read them freely; do not
rewrite one to agree with you. Re-running a script does overwrite its
`verdict.json`, which is unavoidable, so a re-validation says in its notes that
it is one, what the previous verdict recorded, and which of its checks moved —
V4 and V7 both do. A second opinion that disagrees belongs in your own verdict,
argued, as V6's "SECOND, INDEPENDENT RULING" note does.

Ten slices have now been judged this way. The rest of this file is what those
evaluations cost to learn. None of it is theoretical; each paragraph is a
mistake somebody here already made.

## Pin the bundle before the first assertion, and again after the last

A stale bundle has come within one check of a false FAIL twice.

On V4 a cached `index.html` pointed at a superseded asset (`index-8JR9Y1NP.js`),
and that bundle reproduced the already-fixed defect exactly — two `t` params on
all nine affected videos. It is a beautiful negative control and it is not the
code under test. On V7 a concurrent rebuild replaced the asset mid-evaluation
while the cached `index.html` still named the deleted one, and a `no-store`
fetch of that name returned the API's **22-byte 404 body** — a "bundle" that
contains nothing at all and will fail every grep you point at it.

The practice that survived: fetch `index.html` cache-bypassed, read the asset it
names, re-fetch *that* asset from inside the page with `cache: 'no-store'`,
SHA-256 it there, and compare the digest and byte length against
`frontend/dist/assets/<same name>` on disk. Record the sha in the verdict. Do it
before the first assertion and again after the last — other agents rebuild
continuously, and if the hash moves mid-run you re-verify rather than mixing
observations taken from two different bundles.

## Grepping a bundle for a marker string is not proof of a fix

V4 nearly certified a fix by finding `time_continue` in the bundle. The pre-fix
tree already contained that string, in a local helper in
`frontend/src/pipeline/graph.ts` — so the grep would have passed before the fix
as happily as after it. What was asserted instead was that the **old idiom is
absent** (zero occurrences of `includes('?') ? '&' : '?'`), and then that the
behaviour is right in the rendered DOM. Prefer the DOM. A marker string only
tells you a build happened, not which one.

## Playwright does not launch on this machine

`chromium.launch()` times out at 180s, at 0% CPU, with no page and no
navigation — the same wedged macOS XPC service that hangs the Metal shader
compiler. Eight verdicts now record it.

Write the script anyway. It is the durable artifact: it outlives this host, and
the next evaluator re-runs it rather than re-deriving it. Then execute every
assertion as the equivalent DOM query in a real browser against the same URL,
and state that constraint plainly in the verdict's `notes`.

Two refinements are worth copying. V6 **imported the script's own predicates and
ran them over the extracted DOM state**, so the recorded pass/fail is the
script's code deciding rather than a hand-written paraphrase of it — the
strongest form available while the launcher is broken. V8 executed each selector
against the live DOM and corrected the ones that were wrong (`.rs-diffrow.added`
/ `.kept` and `.rs-cos`, not the `pk-*` names first guessed), which is what makes
the committed file a working artifact instead of an untested transcription.

## Never restart the server on 8021

Other agents are working against it. When you need fresh Python, a doctored run
file, or a variant artifact, stand up a **second instance on a spare port**
serving the same `frontend/dist`, verify there, stop it, and confirm 8021 is
still up. Two routes are already proven:

* `create_app(..., runs_dir=<dir>)` over copies in a scratch directory — V6 on
  8022 for its replay states, V2 on 8023 over `demo/validate/fixtures/` (see
  `serve_fixtures()` in `v2_filter.py`).
* An env var the config layer already reads — V7 served its own 9-look artifact
  through `YT_AGENT_CONFLICT_PATH` on 8098 and a second variant on 8099.

Leave the real artifact alone and prove you did: V7 recorded the md5 and mtime
of `.yt-agent/conflicts.json` before and after and showed both unchanged.

## If you loosen a check, prove it still bites

Two evaluators amended a predicate this session, and both of them replayed
states through the amended version to show it had not become a rubber stamp.
This is now the price of touching a check.

The technique: enumerate the states — the page as shipped, the plausible future
page the amendment is for, the original concealment the check was written to
catch, and the *new* unsound mode the amendment could let through — build each
one, run all of them through both the amended and the original predicates, and
tabulate the outcomes in the verdict.

It pays for itself. V6's State C (a signed delta rendered against a baseline the
scorer had withdrawn) is a state the **original** predicate passes and the
amendment fails, which is how you show the amendment is strictly stronger where
it matters. V6's State H caught the evaluator's **own first draft** being a
partial rubber stamp: it accepted a page where the arm under judgement went
ungraded itself, so the amendment gained a check rather than only relaxing
others. V7 replayed four states through its widened predicate and confirmed a
bare integer count still FAILs — the exact regression the check was written for.

## Prefer states the app can produce from data

A state you reached by editing a data file and letting the app render it is
evidence about the app. A state you hand-edited into the DOM proves your
selector works. Say which you used, for each state.

V6's replay was four of each, and it named the reason for every DOM edit: the
panel computes its `decisive` verdict from the same two ranges it prints, so
"non-overlapping gap tagged *within noise*" has no data route and must be
mutated in. That is a fair use. Mutating in a state the app *could* have
produced is not.

## Width sweeps: the two obvious techniques both lie

`resize_window` reports success while leaving `innerWidth` unchanged on this
host — V4 stayed pinned at 1158px through a sweep, and V8 could not hold the
harness's 1440x900 at all. And constraining a container (V4 varied `.app`'s
width) measures wrapping but **cannot fire a viewport media query**, so V4's
820px sample never exercised the 900px breakpoint it was written for, however
confidently the note reads.

V7's technique works: a **same-origin iframe** sized to true CSS pixel widths
with the view clicked open inside it, so `window.innerWidth` really is the
target and the media query evaluates against it. Its sweep at 1440/1100/860/700
shows the 820px query firing and the two columns stacking, which is the thing a
width check is for. If you cannot do that, say the verdict makes no layout claim
— several correctly do.

## A verdict that is not independent must say so

Where the spend limit killed subagents and the orchestrating agent had to
re-check its own fix, the verdicts say **"REDUCED INDEPENDENCE, stated plainly"**
and scope it: which checks it covers, which checks remain the original
evaluator's untouched work. V2, V5 and V8 all carry that disclosure. It is not
an apology; it is part of the evidence, and `status.py` surfaces it on the
status table so a reader of the summary sees it too.

## Things paid for once already, in no particular order

* **Hard-coded literals rot faster than the feature does.** Five of V3's
  expectations were already stale at HEAD before anything broke them, and would
  have read as a regression in the panel. They were replaced by cross-checks
  between the card's own statements of the same number, so a rescore no longer
  looks like a failure. Assert internal consistency, not remembered values.
* **A probe returning a degenerate value decides for the wrong reason.** V2
  found three in one script: `.qpanel tbody` resolved to the *first* `.qpanel`,
  which ships collapsed with 0 characters of `innerText`; `phase == "filter"`
  compared against text `text-transform: uppercase` had already made `FILTER`;
  and a line-height probe on a span whose computed line-height is the keyword
  `normal` yields `NaN`, so its guard was False for any list of any length.
  Check that a probe returns something before trusting what it says.
* **A guarded check that never fired is recorded as absent, with the reason.**
  V2's "selecting it shows its graded cells" is missing from that verdict
  because the option it needed was not in the dropdown — stated, not silently
  dropped.
* **Judge a conjunctive gate clause by clause.** V8's top-level `passed` is
  false, but "V8 failed" is the wrong summary: the loop is built, works and is
  legible; what failed is the hypothesis that it produces a better pack. The
  verdict says so in its first note.
* **Timestamp every count you read.** The corpus moved 59 → 60 → 65 videos
  during a single V5 evaluation. Any number you record is a number as of a
  moment.
* **Name the artifact you judged, because it may not survive you.** V3's 33/33
  was decided against two critique runs that have since been superseded and
  deleted; the verdict is still a true record but nobody can re-derive its
  numbers from the repo. `status.py` now says so on the row automatically, which
  only works because the verdict wrote the run ids down. Write them down.
* **Declare anything you wrote outside your own artifact directory.** Pressing
  an override control during V5 caused the *server* to rewrite
  `experts/job-search/manifest.json`; the evaluator picked that pack because the
  directory is untracked, restored the state, and named the residue. V4b's two
  Chat asks left two conversations in the history rail and it said so.
* **Zero model calls is usually achievable, and where it is not, say so.** V6
  read every number off the rendered page or off disk, and recorded the one
  thing it could not redo — regenerating a Chat review — as "not re-executed"
  rather than papering over it. The provider has been returning
  `402 Insufficient Balance`; an evaluation that quietly skips what it cannot
  afford is worse than one that names the hole.
* **Verdicts may carry more than the harness's schema.** V7 added `driver`,
  `viewport` and `driver_note` fields to record how the run was actually
  performed. `status.py` reads `passed`, `checks` and `started_at` by key and
  everything else by scanning the file's text, so extra keys are safe and are
  the right place for the provenance of the run itself.
